# 4.3 Curated Verticals

> Pick one category, build proprietary data, serve better results than pure GPT. This is the moat YC is really asking about.

---

> [!info] Status: Todo
> This is the "doing things that don't scale" section. Start with one city, one category, 100 seed queries.

---

## Task Checklist

- [ ] Pick one vertical to own first (recommendation: restaurants in one city)
- [ ] Scrape and structure data for that vertical
- [ ] Human-curate top 3 for 100 seed queries
- [ ] Serve curated results instead of AI for known queries
- [ ] Expand to 3 more cities once model is proven

---

## Why One City First

> [!tip] YC's "do things that don't scale" principle
> Don't try to curate everything. Pick Hyderabad restaurants.  
> Manually find the best 3 results for the 100 most-searched queries in that niche.  
> Your results will be demonstrably better than ChatGPT's for that specific vertical.  
> That's your moat. Then you expand.

---

## Data Architecture

```sql
CREATE TABLE curated_results (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  query       TEXT NOT NULL,
  query_hash  TEXT UNIQUE NOT NULL,
  vertical    TEXT NOT NULL,    -- 'restaurants', 'hotels', etc.
  city        TEXT,
  results     JSONB NOT NULL,   -- [{rank, name, description, url}]
  curated_by  TEXT,             -- 'human' | 'ai' | 'hybrid'
  created_at  TIMESTAMPTZ DEFAULT NOW(),
  updated_at  TIMESTAMPTZ DEFAULT NOW()
);
```
